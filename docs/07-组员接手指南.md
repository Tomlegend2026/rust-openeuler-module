## 六个人现在分别做什么

| 成员 | 第一项行动 | 提交物 |
|---|---|---|
| A（组长） | 确认成员与 GitHub 账号，创建仓库并邀请协作者 | 成员表、一次总检查记录 |
| B | 核对实际配置、运行版本和 VM 存放位置 | 环境复核笔记与真实启动截图 |
| C | 按文档在一致环境重新构建模块 | 自己执行的构建日志、发现的问题或检查结论 |
| D | 运行统计逻辑测试，解释 init、借用、所有权、Drop | 自己的代码阅读笔记及边界用例分析 |
| E | 独立复现装卸测试，补充重复加载等负向用例 | 独立测试日志、结果表及问题记录 |
| F | 用原始日志核对报告，整理讲稿并组织彩排 | 报告审阅记录、答辩问题和演示安排 |

详细验收和互评关系见 01-任务分工.md。每人使用独立分支，提交聚焦的 PR；不能为了凑贡献随意改代码。检查无问题时，提交有证据的检查记录也可以。

## 演示顺序

1. 展示任务要求、模块用途和实际环境版本。
2. 展示源码与构建日志，说明本模块由 Rust 编写。
3. 在 openEuler 终端进行加载、查看日志、卸载并核对模块列表。
4. 展示 10 轮结果和原始日志，解释统计值。
5. 说明尚未覆盖的错误路径和有限测试的边界。

正式汇报前至少安排一次全员彩排。截图必须来自真实实验；当前仓库已有文本证据，但尚未提供完整演示录像。原内核及安装前快照保留作恢复用途。
