# 组内检查清单

复核必须留下文件、日志或 PR 链接。未检查的项目不要勾选。

- [ ] A：组号、名单、分享日期明确；每个检查任务有负责人。
- [ ] 全员：已阅读模块源码，能解释 init 与 Drop 的先后顺序。
- [ ] D：算法6项测试通过，能说明空输入与溢出的处理。
- [ ] B：系统确实是 openEuler，架构为 x86_64，已填真实版本。
- [ ] B/C：固定内核提交、Rust 1.73.0、bindgen 0.65.1 与配置吻合。
- [ ] C：完整构建成功，已启动新内核，.ko 的 vermagic 与运行内核匹配。
- [ ] E：人工装卸一次成功，日志内容正确。
- [ ] E：10轮测试结果与新增日志相符，无新增相关异常。
- [ ] E：重复加载、卸载不存在模块的预期失败已记录。
- [ ] B或E：非作者按文档复现成功，发现的步骤缺漏已修正。
- [ ] F：报告没有把预测、示例或主机测试写成内核实测。
- [ ] F：Drop 日志的语义、代码来源与许可说明正确。
- [ ] A/F：贡献记录与实际提交对应，全员完成一次答辩彩排。

评审记录格式：检查人、文件/范围、检查方法、发现的问题、修改提交、复核人。没有问题也说明验证覆盖了什么。
