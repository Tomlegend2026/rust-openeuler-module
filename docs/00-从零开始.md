# 我们究竟要做什么

老师要求的是：用 Rust 写一个能进入 openEuler 内核工作的模块，并展示它在系统运行期间被加入和移除。这里的“动态”指无需为每一次装卸重启系统；第一次为启用 Rust 而安装并启动实验内核，可能需要重启。

可以把这次任务分为三件事：读懂现成初稿；在正确的系统里把它跑通；用真实证据说明它为什么能工作。

## 你作为组长现在先做什么

1. 把本目录上传 GitHub，邀请组员。按照 docs/01-任务分工.md 把六个人填入 A～F。
2. 让 B、C 一起检查有没有 openEuler 虚拟机；没有则按 environment/搭建步骤.md 建立统一实验环境。
3. 把不同检查任务发给组员。所有人先看下面的三份材料，之后各自修改对应部分。
4. 收到结果时看具体提交和证据，不只听“我看过了”。遇到错误，提供版本、完整命令及输出。

你不必先学会编译整个内核再组织分工。你的核心交付是确保每个检查点有人验证、最后能够演示并解释。

## 全员先看哪三份材料

- module/rust_team2.rs：真正的内核模块，很短，先找到 `init` 和 `drop`。
- docs/05-模块原理.md：逐步解释加载、计算、保存状态和释放。
- report/实验报告.md：理解最终需要呈现的全过程。

## 每个人今天就能开始的事情

有 Rust 的 Linux 终端可以运行 `bash scripts/test-logic.sh` 和学习示例。即使没有 openEuler，也能读懂统计代码、检查报告、准备答辩。没有 Rust 时可以先阅读，不要在任意机器上安装或加载内核模块。

## 什么才算完成

必须能展示：openEuler 与运行内核版本；模块编译生成 `.ko`；加载成功；内核日志里出现正确统计结果；卸载成功；重复装卸仍然正常。日志和截图来自自己的实验，不能直接复制示例文本。

初稿已解决“写什么、按什么步骤做、如何记录”的问题。仍需你们完成环境复现、现场测试、个人笔记和真实贡献记录，才能形成可信的课程作业。
