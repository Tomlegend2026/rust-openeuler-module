# 我们究竟要做什么

老师要求的是：用 Rust 写一个能进入 openEuler 内核工作的模块，并展示它在系统运行期间被加入和移除。这里的“动态”指无需为每一次装卸重启系统；第一次为启用 Rust 而安装并启动实验内核，可能需要重启。

可以把这次任务分为三件事：读懂项目材料；在正确的系统里把它跑通；用真实证据说明它为什么能工作。

## 使用顺序

1. 阅读环境说明和复现流程，确认 Windows、openEuler、内核源码和工具链的执行位置。
2. 阅读模块源码、模块原理和实验报告，了解模块入口、统计逻辑、动态装卸和资源释放。
3. 在匹配的 openEuler 实验内核中构建模块，按复现流程运行装卸测试。
4. 对照原始日志、测试结果和报告检查结论；发现问题时记录版本、命令和完整输出。

## 全员先看哪三份材料

若还没有实验环境，先打开 [下载链接与安装位置](../environment/下载链接与安装位置.md)，其中明确区分 Windows 上下载软件和 openEuler 终端内执行实验的步骤。

- module/rust_team2.rs：真正的内核模块，很短，先找到 `init` 和 `drop`。
- docs/05-模块原理.md：逐步解释加载、计算、保存状态和释放。
- report/实验报告.md：理解最终需要呈现的全过程。

## 每个人今天就能开始的事情

有 Rust 的 Linux 终端可以运行 `bash scripts/test-logic.sh` 和 Python 辅助测试。即使没有 openEuler，也能检查统计代码、证据核验工具和报告。没有 Rust 时可以先阅读，不要在任意机器上安装或加载内核模块。

## 什么才算完成

必须能展示：openEuler 与运行内核版本；模块编译生成 `.ko`；加载成功；内核日志里出现正确统计结果；卸载成功；重复装卸仍然正常。日志和截图来自自己的实验，不能直接复制示例文本。

仓库提供源码、环境说明、复现脚本、测试证据和汇报材料。最终结论应以实际运行日志和版本信息为准。
